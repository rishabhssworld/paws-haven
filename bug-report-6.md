| #   | What I saw                                                          | Where I found it                 | Cause                                                                  | Fix                                                         |
| --- | ------------------------------------------------------------------- | -------------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------------- |
| 1   | The page stayed on “Loading…” with no Console error.                | Empty `catch` block              | The error was caught but hidden.                                       | Logged the error and showed a friendly message.             |
| 2   | JavaScript could not use `await` in `loadPhoto`.                    | `loadPhoto` function declaration | The function was not marked `async`.                                   | Changed it to `async function loadPhoto(breed)`.            |
| 3   | Console said `response.json is not a function`.                     | The `fetch` line in `loadPhoto`  | `fetch` had not been awaited, so `response` was still a Promise.       | Added `await` before `fetch`.                               |
| 4   | The image address became `undefined`.                               | The `response.json()` line       | The JSON response had not been awaited, so `data` was still a Promise. | Added `await` before `response.json()`.                     |
| 5   | The image address was still `undefined`.                            | `camPhoto.src` assignment        | The API returns the photo URL in `data.message`, not `data.url`.       | Changed it to `data.message`.                               |
| 6   | A mistyped breed caused a broken image instead of an error message. | After the `fetch` call           | `fetch` does not throw automatically for a 404 response.               | Checked `response.ok` and threw an error when it was false. |
